Task (1)
-----------
We need to restructure this project into a docker-compose oriented cloud project where just running docker-compose up deploys it

Create a module for each Agent so it runs in it's own docker module behind an nginx proxy using Python and Gunicorn, not typescript.

Agent to Ollama Cloud API needs to handled with a shared utility included in the module which also handles the API key.

Create an Orchestrator module for managing all of the Agents and handling communication between them - Use redis for this

The UI is also it's own docker module using Typescript.

The Database is it's own docker module.

Scrap drizzle, as when the agents become their own containers they can't use Drizzle.

The orchestrator is not a simple pipeline. It manages queues, conditional flows, retries, and parallel work. Some agents trigger others, some run independently on a schedule, some fan out. That logic lives in the orchestrator, not in the agents.

The UI does not talk to the agents directly, and only the orchestrator if it needs to. It reads from the shared database. Agents write events and results there. The UI is a reader.

Redis is the glue between agents and the orchestrator. Jobs, events, and triggers all flow through it.

Each agent in its own container means you can read and maintain one agent without touching the others. That simplicity and maintainability is worth a few extra containers.

For "each agenda as a module," a council is a module (you subscribe to it). A meeting is a row inside that module (the agenda you receive). Both live in Postgres. No need for a container per agenda.

docker-compose up starts: nginx, ui, orchestrator, each agent container, redis, postgres.

The system is now much more maintainable and easier to grasp and explore.
